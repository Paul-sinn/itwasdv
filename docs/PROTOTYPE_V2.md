# 시제품 v2 지시서 (초안)

> 초안. v1 플레이 테스트를 통과하고, 아래 "[정해야 함]"을 사용자가 정하기 전에는 만들지 않는다.
> 숫자는 이미 `data/balance.json`의 `tune` 묶음과 시뮬(`tools/delivery_sim.py`)에 있는 것을 그대로 쓴다.

## 이 시제품으로 알아낼 것 (딱 하나)

**"강화 말고 튜닝(큐브)으로도 시간당 수익을 올리는 게 재밌고, 돈을 강화에 쓸지 튜닝에 쓸지 고민되나?"**

v0 플레이 테스트 뒤 사용자 의견: "강화 말고도 시간당 수익을 올릴 방법이 다양했으면 좋겠다 → 큐브로 차 튜닝".

## 범위

**만드는 것**
- 큰 화면 차고에 [엔진 강화] / [튜닝] 두 칸 (탭)
- 튜닝 굴리기: 돈 내고 누르면 일정 확률로 등급이 오름. 실패하면 그대로 (내려가지 않음)
- 등급에 따라 시간당 수익 보너스
- 튜닝 연출 (등급업 순간), 작은 화면 동네 트럭에 등급 색 표시
- 저장 (예전 저장 파일은 "일반"으로 시작)

**안 만드는 것** (`docs/IDEAS.md`에 있음)
튜닝 키트(택배 상자에서 공짜 튜닝), 튜닝 데이(매주 등급업 2배 등), 부캐 트럭, 회사, NPC, 그 밖의 돈 수급처

## 튜닝 부위 (제안. 2026-11-10 사용자 요청: "RPG 장비칸처럼 부위가 여러 개였으면")

RPG 장비칸처럼 트럭 부위 8칸. 엔진은 지금처럼 강화(★), 나머지 7칸은 튜닝(큐브)으로 올린다.
부위마다 시간당 수익을 올리는 "방법"이 다르게:

| 부위 | RPG로 치면 | 실제로 뭐냐면 | 게임 효과 (등급이 오를수록 커짐) |
|---|---|---|---|
| 엔진 | 무기 | 차의 심장 | 강화 ★ (지금 그대로). 시간당 수익의 뼈대 |
| 터보 | 보조무기 | 엔진에 공기를 더 밀어 넣어 힘을 키우는 장치 | 시간당 수익 +% |
| 타이어 | 신발 | 바퀴 고무 | **대박 배송 확률**: 집에 들를 때 가끔 돈을 몇 배로 |
| 짐칸 | 상의 | 택배를 싣는 뒷부분 | **대박 배송 배수**: 대박일 때 ×2 → ×3 … (타이어와 짝: 치명타 확률·피해처럼) |
| 서스펜션(쇼바) | 하의 | 덜컹거림을 잡아 주는 스프링 | 퍼짐 확률 −% (엔진을 덜 흔들어서) |
| 연료 탱크 | 망토 | 기름통 | 꺼둔 동안 최대 시간 +시간 (8시간 → 더 길게) |
| 내비게이션 | 투구 | 길 안내 기계 | 꺼둔 동안 수익 비율 +% (50% → 더 많이) |
| 엔진오일 | 반지 | 엔진 속 윤활유 | 강화 비용 −% |

## 계산식 (숫자는 전부 `data/balance.json`의 `tune`)

```
등급:        일반 → 레어 → 에픽 → 전설                   (tune_grades)
수익 보너스:  +0%  / +10% / +25% / +50%                  (tune_bonus)
튜닝 1번 비용 = tune_cost_hours[지금 등급] × base_hourly  → 100원 / 1,500원 / 20,000원 (고정 금액)
등급업 확률:  일반→레어 15% / 레어→에픽 5% / 에픽→전설 1.5% (tune_up_chance)
시간당 수익 = 엔진 강수 수익 × (1 + 튜닝 보너스)
```
- 엔진 강화 비용·스페어값은 튜닝 보너스와 상관없다 (시뮬과 같음. 강화 비용은 "엔진 강수 수익의 N시간치")
  → 튜닝을 올리면 강화에 필요한 돈이 더 빨리 모인다. 이게 "튜닝할까 강화할까" 고민거리
- 엔진이 퍼져도 튜닝 등급은 그대로 (시뮬과 같음)
- 고장 중에는 수익 0이라 튜닝 보너스도 0
- 꺼둔 동안 수익에도 보너스 반영
- 평균으로 보면 전설까지 약 136만 원 (일반→레어 약 667원, 레어→에픽 약 3만 원, 에픽→전설 약 133만 원)
- 굴리기는 `scripts/core/tune.gd` 한 파일에만 (강화의 `enhance.gd`처럼. 화면 코드에서 확률 계산 금지)

## [정해야 함] (사용자)

추천대로 가도 되면 "추천대로"만 말해 주면 된다.

0. **부위 목록** (위 표): 이대로 / 빼거나 더할 부위
1. **큐브 방식** (부위마다):
   - A (추천): **등급만 올리기**. 부위마다 등급(일반→레어→에픽→전설), 큐브로 등급업, 실패해도 그대로.
     등급마다 효과 크기는 정해져 있음. 간단하고 시뮬 구조와 같음
   - B: 메이플 잠재능력처럼 **옵션 줄 굴리기**. 부위마다 옵션 2~3줄이 큐브를 쓸 때마다 랜덤으로 바뀜
     (효과 종류까지 랜덤). 재미는 크지만 정할 게 많고 시뮬을 새로 맞춰야 함 → v3 추천
   - C: A + 등급 안에서 수치만 랜덤 (예: 터보 레어 = +8~12%, 다시 굴려서 좋은 수치 노리기)
   - 부위가 여러 개가 되면 위 계산식(튜닝 1칸)과 시뮬을 부위 수에 맞게 다시 맞춰야 함
2. **비용**: 추천: **시뮬 그대로 고정 금액** (100 / 1,500 / 20,000원).
   다른 안: 강화처럼 "지금 수익의 N시간치" (강수가 높으면 튜닝도 비싸짐)
3. **등급 색**: 추천: 일반 회색 / 레어 파랑 / 에픽 보라 / 전설 금색
4. **튜닝 연출 세기**: 추천: 강화보다 짧게 (뜸 0.3초, 등급업이면 번쩍 + 등급 글자 커짐, 실패는 조용히 "그대로")

## 화면

**큰 화면 차고**
- 위에 [엔진 강화] [튜닝] 두 칸. 처음엔 [엔진 강화]
- [튜닝] 칸: 지금 등급(색 글자), 지금 보너스 → 다음 등급 보너스, 등급업 확률, 비용,
  돈 모자라면 "약 N분 뒤 가능", [튜닝] 버튼, 결과 한 줄, 튜닝 통계(누른 횟수, 등급업 횟수)
- 전설이면 "최고 등급" + 버튼 숨김
- 고장 중에도 튜닝은 된다 (수익이 0이라 돈은 안 모이지만, 이미 있는 돈으로)

**작은 화면**
- 트럭 위나 옆에 등급 색 점 하나 (일반이면 없음). 작은 화면은 그대로 보기 전용

## 작업 순서

각 단계 끝나면 커밋. 사용자가 "쭉 진행"이라고 하면 멈추지 않고 이어서.

**1단계: 계산 코드**
- `balance.gd`에 `tune` 묶음 읽기·검사 (길이: 등급 4개, 비용·확률 3개, 보너스 4개, 확률 0~1)
- `tune.gd`: 비용, 확률, 굴리기(난수 생성기를 밖에서 넣음), 막힌 이유(돈 부족 / 최고 등급)
- `economy.gd`: 시간당 수익에 튜닝 보너스, 강화 비용은 보너스 빼고
- `game_state.gd`: 튜닝 등급, 통계 / `save.gd`: 저장·읽기 (없으면 일반)
- 테스트: 등급별 10만 번 굴려서 확률 1%p 안쪽, 비용 정답 값, 보너스 반영, 강화 비용은 그대로, 퍼져도 등급 유지
- 완료 기준: 테스트 전부 통과

**2단계: 화면**
- 큰 화면 차고 두 칸, 튜닝 칸 내용, 작은 화면 등급 색 점
- 치트 키: F6 튜닝 등급 +1 (최고 등급까지)
- 완료 기준: `check_garage`처럼 진짜 클릭으로 일반 → 전설까지, 돈 부족·최고 등급 화면 확인

**3단계: 연출 + 동네 1시간 수익**
- 튜닝 연출 (위 4번)
- 완료 기준: 등급마다 1시간 수익이 "엔진 수익 × (1 + 보너스)"와 1% 안쪽 (`check_town_hour`에 더함)

## 플레이 테스트 (사용자가 직접)

30분 플레이 + F4로 18강, F6 없이 튜닝 직접 굴려 보기.

1. 튜닝 버튼 누를 때 강화와 다른 재미가 있나?
2. 돈을 강화에 쓸지 튜닝에 쓸지 고민되나?
3. 에픽 → 전설 1.5%를 계속 굴려 보고 싶나?
4. 등급이 오른 게 동네(작은 화면)에서도 느껴지나?
5. 강화만 있을 때보다 더 오래 켜 두고 싶나?

"아니오"가 2개 이상이면 기능을 더 붙이지 말고 숫자(`tune` 묶음)와 연출부터 고친다.
