# 시제품 v1 지시서

> 2026-11-10 사용자 확정 ("추천대로"). 0~4단계를 멈추지 않고 이어서 진행 (사용자 요청).
> 창 담당 / 동네 담당 두 에이전트가 나눠서 병렬로 작업한다 (아래 "나눠 맡기").

## 이 시제품으로 알아낼 것 (딱 하나)

**"구석의 작은 동네는 켜둬도 안 거슬리고, 전체 화면으로 들어가서 강화하는 흐름이 자연스럽나?"**

v0 플레이 테스트에서 "아니오"가 나온 4번(켜둔 채 다른 일 할 때 거슬림)을 고치는 시제품이다.
v0의 가로 띠 대신 사용자가 원래 생각한 구조(작은 화면 + 전체 화면)로 바꾼다.
강화 규칙, 돈 계산, 저장은 v0 그대로 쓴다.

## 범위

**만드는 것**
- 작은 화면: 오른쪽 아래 구석의 꼬불꼬불한 길, 집 여러 채, 트럭이 집마다 들렀다 감
- 전체 화면: 같은 동네를 크게 + 차고(강화) 화면을 크게
- 두 화면 오가기 (상태는 그대로 이어짐)
- 알림 영역(시계 옆) 아이콘

**안 만드는 것** (전부 `docs/IDEAS.md`에 있음. 손대지 말 것)
튜닝(큐브), 회사 짓기, NPC, 부캐 트럭, 기사 고용, 택배 상자·극한 배송 등 돈 수급처,
지역 확장, 취업 단계, 스팀 연동, 진짜 그림, 소리.
전체 화면에 이것들이 들어갈 빈 자리(회색 버튼 등)도 만들지 않는다.

## 화면

**작은 화면 (평소, 켜면 항상 이 화면)**
- 주 모니터 오른쪽 아래, 작업표시줄 바로 위 (시계 쪽 구석)
- 꼬불꼬불한 길 하나, 길가에 집 여러 채, 길 끝에 물류센터
- 트럭이 길을 따라가다 집 앞에서 1~2초 멈춤 → "+금액" → 다음 집 → … → 물류센터로 돌아옴 → 반복
- 구석에 ★ 숫자와 돈만 작게
- 고장이면 트럭이 멈추고 연기 (v0 같음)
- 투명 배경, 테두리 없음, 항상 위, 보이는 것 말고는 클릭이 뒤 창으로 통과 (v0 같음)

**전체 화면**
- 들어가기: 작은 화면 클릭, 알림 영역 아이콘 클릭
- 나가기: Esc 또는 [작게] 버튼 → 작은 화면으로
- 같은 동네를 크게 보여줌 (트럭은 계속 움직임)
- 차고(강화) 화면: v0 패널 내용 전부(확률, 비용, 스페어값 남기기, 고장·스페어, 통계)를
  크게, 강화 연출도 화면 크기에 맞게 더 크게
- 복귀 팝업은 작은 화면 위에 (v0 같음)

**돈 계산**
- v0 그대로: 시간당 수익, 강화 비용, 스페어, 꺼둔 동안 수익, 퍼짐 구간 스페어값 남기기
- 2026-11-10 사용자 결정 (balance.json v0.4): 20강부터 시간당 수익이 1강마다 1.3배 (19강까지는 1.1배),
  스페어는 고정 50,000원. 강화 비용은 "그 강수 수익의 N시간치" 그대로 (자세히는 `docs/PROTOTYPE_V0.md` 계산식)
- 집에 들를 때마다 돈을 받는다: 시간당 수익 ÷ 3600 × (지난번 받은 뒤 흐른 초, 멈춘 시간 포함)
  → 1시간 동안 받은 돈의 합 = 시간당 수익 (길 모양, 멈춤 시간과 상관없이)

## 정한 것 (2026-11-10 사용자: "추천대로")

1. **작은 화면 크기**: 가로 480 × 세로 220 (`feel.gd`의 `SMALL_SIZE`)
2. **작은 화면에서는 강화 안 됨**. 작은 화면은 보기 전용, 클릭하면 전체 화면
3. **큰 화면 띄우는 방식은 사용자가 설정에서 고름** (2026-11-10 사용자 추가):
   - 전체 화면 (기본): 주 모니터를 꽉 채우는 테두리 없는 화면
   - 창 모드: 테두리 있는 보통 창. 크기 조절 가능 (처음 1600x900, 최소 1280x720)
   - 큰 화면에 [설정] 버튼 → "화면: 전체 화면 / 창 모드". 고른 값은 저장돼서 다음에 켜도 유지
   - 이 문서에서 "전체 화면 차고"·"전체 화면 오가기"의 "전체 화면"은 큰 화면(`Mode.FULL`)을 뜻한다.
     창 모드로 띄워도 같은 큰 화면이다
4. **집 5채, 1.5초 멈춤** (`feel.gd`)

## 나눠 맡기 (병렬 작업)

두 에이전트가 각자 git 작업 폴더(worktree)·브랜치에서 일하고, 끝나면 합친다.
겹치는 파일은 `scripts/ui/screen_mode.gd`(두 화면 오가기의 "약속")뿐이고, 그 약속은 바꾸지 않는다.

| | 창 담당 (`v1-window`) | 동네 담당 (`v1-town`) |
|---|---|---|
| 단계 | 0단계 기술 확인, 2단계 오가기, 4단계 오가기 오래 켜두기 | 1단계 작은 화면 동네, 3단계 전체 화면 차고 |
| 파일 | `screen_mode.gd`(속), `desktop_window.gd`, 알림 영역 아이콘, `click_region.gd`, `project.godot`, `tests/check_desktop.*`, `tests/soak_desktop.ps1`, 새 오가기 확인 | `main.gd`, 동네·트럭·차고 화면 (`band.gd` 대신 새 파일), `garage_panel.gd`, `scripts/core/`, `tests/check_band_hour.gd`·`check_garage.gd`·`check_save.gd`, 단위 테스트 |
| `feel.gd` | "v1: 화면 두 개 (창 담당)" 칸에만 | "v1: 작은 화면 동네 (동네 담당)" 칸과 기존 칸 |

**약속 (`screen_mode.gd`)**
- `enum Mode { SMALL, FULL }`, `var mode`, `signal mode_changed(mode)`
- `enter_full()`, `enter_small()`: 창을 바꾸고 `mode_changed`를 보냄
- `rects_provider`: 작은 화면(투명)에서 클릭 받을 사각형 목록을 돌려주는 함수. `main.gd`가 넣어줌
- `is_transparent()`: 지금 창이 투명(바탕화면 위)인가. 화면 배경을 칠할지 정할 때
- `enum FullStyle { FULLSCREEN, WINDOWED }`, `var full_style`, `signal full_style_changed(style)`,
  `set_full_style(style)`: 큰 화면을 전체 화면 / 창 모드로. 실제 창 바꾸기 + 설정 저장(`user://settings.cfg`)은
  창 담당, 큰 화면의 [설정] 버튼과 고르는 화면은 동네 담당
- 창 모드에서는 사용자가 창 크기를 바꿀 수 있다 → 화면 내용은 창 크기가 바뀔 때마다 다시 배치 (동네 담당,
  최소 1280x720에서도 안 깨지게)
- Esc → 작은 화면 (창 담당), 알림 영역 아이콘 → 전체 화면 (창 담당)
- 작은 화면 클릭 → `enter_full()`, 전체 화면 [작게] 버튼 → `enter_small()` (동네 담당, `main.gd`)
- 화면 내용은 `mode_changed`를 받으면 `get_viewport_rect().size`에 맞춰 다시 배치 (동네 담당)

## 미리 확인할 기술 위험 (0단계)

v0에서 직접 확인한 것: 투명 창은 "보이는 것 = 클릭 받는 곳". 투명 설정은 켤 때만 바꿔봤다.

- 실행 중에 투명 작은 창 ↔ 불투명 전체 화면을 오가도 화면이 깨지지 않나
- 알림 영역 아이콘: Godot 4.6.3에 `StatusIndicator` 노드가 있다(문서 확인함). Windows에서 실제로
  아이콘이 뜨고 클릭이 들어오는지
- 안 되면 원인과 우회 방법을 정리해서 보고. 혼자 큰 구조를 바꾸지 말 것

## 작업 순서

각 단계가 끝나면 멈추고 확인받을 것. 단계마다 커밋.

**0단계: 기술 확인**
- 위 두 가지를 작은 실험으로 확인하고 결과 보고
- 완료 기준: 둘 다 되거나, 안 되는 것의 우회 방법을 사용자가 고름

**1단계: 작은 화면**
- 구석 위치, 꼬불꼬불한 길, 집 들르기, ★·돈 표시. v0 가로 띠는 없앤다
- 완료 기준:
  - 1시간(F2로 1분) 돌렸을 때 번 돈이 시간당 수익과 1% 안쪽
  - 빈 곳 클릭은 뒤 창으로 통과 (v0 `check_desktop`처럼 자동 확인)

**2단계: 전체 화면 오가기**
- 들어가기(작은 화면 클릭, 알림 영역 아이콘), 나가기(Esc, [작게])
- 완료 기준: 100번 오가도 돈·강수·트럭 위치가 그대로 이어지고, 화면이 깨지지 않음

**3단계: 전체 화면 차고**
- v0 차고 패널을 전체 화면용으로 크게 옮기고, 강화 연출을 크기에 맞게 다듬기
- 치트 키 F1~F5는 두 화면 모두에서 동작
- 완료 기준: v0 `check_garage`와 같은 확인(0~30강, 퍼짐 → 수리)이 전체 화면에서 전부 통과

**4단계: 오래 켜두기 + 플레이 테스트 준비**
- 작은 화면으로 2시간 켜두기 (v0 `soak_desktop`)
- 중간중간 전체 화면을 오가도 메모리·화면 자원이 늘지 않음

## 플레이 테스트 (사용자가 직접)

30분 동안 작은 화면을 켜두고 평소 일 + 강화하고 싶을 때 전체 화면으로 들어가기.

1. 작은 화면을 켜두고 다른 일 할 때 안 거슬리나?
2. 트럭이 집에 들르는 걸 가끔 보게 되나? (보는 재미)
3. 강화하고 싶을 때 전체 화면으로 들어가는 게 귀찮지 않나?
4. 전체 화면 강화가 v0 패널보다 더 두근거리나?
5. 다시 작은 화면으로 돌아가는 게 자연스럽나?

"아니오"가 2개 이상이면 기능(튜닝 등)을 붙이지 말고 화면 구조부터 다시 본다.
통과하면 다음 지시서는 전체 화면에 튜닝(큐브)을 넣는다.
