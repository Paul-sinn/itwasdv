## 이 시제품으로 알아낼 것 (딱 하나)

**포인트 59개로 5개(다 찍으려면 120)를 고르는 것이 "빌드를 짜는 재미"가 되는가?**

## 정한 것

| 항목 | 정한 것 | 근거 |
|---|---|---|
| 능력치 | 상하차 속도, 친절, 협상, 노하우, 정비 지식. **처음부터 전부 열림** | 스냅샷 6번 |
| 포인트 | v5에서 쌓이던 `ability_points`(레벨당 1, 10레벨마다 +2, 만렙까지 59)를 쓴다. 1포인트 = 능력치 1 | |
| 초기화 | 무료, 횟수 제한 없음. 전부 0으로 돌리고 포인트를 돌려받음. 잘못 누르지 않게 버튼을 두 번 눌러야 함 (첫 번째: "한 번 더 누르면 초기화", 3초 뒤 원래대로) | 스냅샷 6번. 두 번 누르기는 조율자가 정함 |
| 적용 범위 | **내 트럭(트럭 0)에만.** 꺼둔 동안에도 평균값으로 적용 | 기획서 16.5 |
| 상하차 속도 | 집 앞 정차 시간 × (1 − 1% × 포인트). 최대 30포인트 = 30% | 스냅샷 |
| 협상 | 배송 단가 × (1 + 1% × 포인트). 최대 20 = +20%. 기름값·정비비는 단가의 %라 같이 커짐. (기업 계약 금액은 v7) | 스냅샷 |
| 친절 | 팁 확률 = 기본 팁 확률 + 0.5% × 포인트 (최대 30 = +15%p). 배송 1건마다 굴림. 팁 = (협상이 적용된) 단가 × 팁 비율. 기름값·정비비 안 뗌 | 스냅샷 + 기획서 "기본 팁 확률(0보다 큼)에 더함", "팁 금액은 단가에 비례" |
| 노하우 | 꺼둔 동안 배송(창고 상한 시간까지)에도 경험치: 켜 둔 것(`xp_per_parcel`)의 2.5% × 포인트 (최대 20 = 50%). 만렙 뒤엔 평판으로 (지금 `Driver.add_xp` 동작 그대로) | 스냅샷 6·7·8번 |
| 정비 지식 | 스페어 드랍 확률 × (1 + 5% × 포인트). 최대 20 = 2배. 켜 둔 동안·꺼둔 동안 둘 다 | 스냅샷, Q2-1 |
| 화면 자리 | 물류센터 화면의 기사 영역 (레벨·경험치 아래) | v6a 건물 화면 |

## 옮길 숫자 (`data/balance.json`, `docs/numbers-source.md`에 기록)

```json
"abilities": {
  "unload":  { "per_point": 0.01,  "max_points": 30 },
  "kind":    { "per_point": 0.005, "max_points": 30 },
  "nego":    { "per_point": 0.01,  "max_points": 20 },
  "knowhow": { "per_point": 0.025, "max_points": 20 },
  "mech":    { "per_point": 0.05,  "max_points": 20 }
}
```

**임시 시작값 (시트에 없음. 조율자가 정함 → `QUESTIONS.md` Q18):**

| 키 | 값 | 이유 |
|---|---|---|
| `trip.tip_base_chance` | 0.02 | "0보다 큼"만 정해져 있음. 능력치 없이도 가끔 팁이 뜨는 정도 |
| `trip.tip_rate` | 1.0 (팁 = 단가 1건치) | 친절 최대(17%)일 때 수입 약 +17% → 협상 최대(+20%)와 비슷하게 |

## 코드 약속

```gdscript
## scripts/core/ability.gd (새 파일. 화면 없이 도는 계산)
static func ids(b: Balance) -> Array[String]                       ## ["unload", "kind", "nego", "knowhow", "mech"] (json 순서)
static func points(state: GameState, id: String) -> int             ## 그 능력치에 찍은 포인트
static func max_points(b: Balance, id: String) -> int
static func value(b: Balance, state: GameState, id: String) -> float ## 지금 효과 = 포인트 × per_point (예: 협상 7 → 0.07)
static func points_left(state: GameState) -> int                    ## ability_points − 찍은 합
static func can_add(b: Balance, state: GameState, id: String) -> bool
static func add(b: Balance, state: GameState, id: String) -> bool   ## 1포인트 찍음. 못 찍으면 false
static func reset(state: GameState) -> void                         ## 전부 0

## game_state.gd
var abilities: Dictionary = {}     ## 능력치 id → 찍은 포인트 (없으면 0)

## trip.gd: advance 이벤트에 추가
##   { "type": "tip", "pay": int }  (바로 앞 배송에서 팁이 나옴. 돈은 이미 더해짐)
## apply_offline 결과: "xp" 가 노하우만큼 0보다 클 수 있음 (지금은 늘 0). 팁은 "money"에 평균값으로 포함
```

- 능력치는 `i == 0`(내 트럭)일 때만 계산에 들어간다. `Trip`의 함수 인자가 바뀌면(예: state가 필요해짐) 보고에 "바뀐 약속" 표로 적는다. 화면이 부르는 `Trip.hourly_income`, `Trip.parcel_pay` 등이 능력치를 반영해야 한다 (화면의 "시간당 수입"이 실제와 같게).
- 팁·드랍 굴리기는 `trip.gd`에만.
- 저장 형식을 올리고 `abilities`를 넣는다. 옛 형식(3~6)은 그대로 읽음(능력치 없음). 저장 파일의 값은 0~최대로 자르고, 합이 `ability_points`를 넘으면 전부 0으로.
- `ability_points`는 "받은 포인트 합" 그대로 둔다 (찍어도 안 줄어듦. 남은 것은 `points_left`).

## 화면

| 항목 | 정한 것 |
|---|---|
| 능력치 목록 | 물류센터 화면 기사 영역에 5줄: 이름 · 한 줄 설명 · "7/20" · 지금 효과("단가 +7%") · [+] 버튼. 포인트가 없거나 최대면 [+] 꺼짐 |
| 남은 포인트 | 목록 위에 "남은 포인트 N" |
| [초기화] | 위 "정한 것"대로 두 번 누르기 |
| 예시 빌드 | 목록 아래 글 4줄: 돈벌이(협상 + 친절), 스피드(상하차 속도 + 협상), 쉬엄쉬엄(노하우 + 협상), 강화(정비 지식 + 협상). 글만 (한 번에 찍어 주는 버튼 없음) |
| 팁 | 동네에서 팁이 나오면 그 집에 "+금액" 옆에 "팁!" (색 다르게). `visible_rects()`는 기존 "+금액" 자리 안에서 |
| 알림 | 찍을 포인트가 남아 있으면 작은 화면 구석 줄의 레벨 옆에 점 하나 (물류센터에 가 보라는 표시). 다 찍으면 사라짐 |
| 꺼둔 동안 요약 | 노하우 경험치가 있으면 "경험치 +N" 한 줄 |
| 글자 | 능력치 이름: 상하차 속도 / 친절 / 협상 / 노하우 / 정비 지식. en: Unloading / Kindness / Negotiation / Know-how / Mechanics (임시) |

화면 코드에서 효과를 계산하지 않는다 (`Ability.value`, `Trip.*`만 읽음). 표시용 %(값 × 100)는 괜찮다.

## 시뮬 (`tools/tune_sim.py`)

- 가상 유저가 포인트를 받으면 바로 찍는다. 빌드 4개(위 예시 빌드. 주 능력치를 최대까지 → 협상 → 남으면 상하차)를 `--build`로 고르고, 기본은 돈벌이.
- 보고: ① 능력치마다 최대로 찍었을 때 "수입 몇 %와 같은지" 표 (+10, +18 기준. 노하우·정비 지식은 수입이 아니라 각각 "만렙까지 며칠 줄어드는지", "며칠에 스페어 1개"로) ② 빌드별 30일째 단계·만렙 날짜 ③ 능력치를 넣은 뒤 30일 판정(가볍게 +18, 열심히 +20)이 그대로인지. 안 맞으면 비용표 제안 (json에 넣지 않음).

## 플레이 테스트 (사용자가 직접)

1. 능력치 5개의 설명만 읽고 무엇을 찍을지 고를 수 있었는가?
2. 찍은 뒤 달라진 것이 느껴졌는가? (수입 숫자, 팁, 트럭이 집 앞에서 덜 섬)
3. 초기화를 써 봤는가? 다시 찍는 것이 귀찮지 않았는가?
4. 포인트가 모자라서 "뭘 포기할지" 고민했는가?
5. 예시 빌드 글이 도움이 됐는가?
