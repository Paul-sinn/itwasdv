## 바뀌는 규칙 (계산)

1. **오버부스트:** 바퀴 출발할 때 확률(줄 합, 최대 1)로 걸리고, 걸리면 **그 바퀴 전체의 운전 속도가 `overboost_mult`(2)배** = 달리는 초 ÷ 2. 싣는 시간·정차 시간은 그대로. "10초 동안"은 없어짐.
2. **소수점 적재량은 확률로:** 적재량 = `base_cargo × (1 + 적재량 줄 합)`. 소수점이 남으면 바퀴 출발할 때 굴려서 그 확률로 +1건 (21.6건 → 60%로 22건, 40%로 21건). 평균 계산(시간당 수입, 꺼둔 동안, 시뮬)은 소수점 그대로 쓴다. 굴리기는 `trip.gd`에만.
3. **실패 = 모든 단계에서 단계 유지.** 지금 코드 그대로라 바꿀 것 없음. 테스트 한 줄로 못 박아 둠 (+0~+29 실패 때 단계가 안 줄어듦).

## 코드 약속 (바뀌는 것만)

```gdscript
## trip.gd
static func cargo(b: Balance, t: TruckState) -> float   ## 평균 적재량 (소수점 그대로. 예: 21.6). 예전엔 int
## 이번 바퀴에 실제로 실은 건수는 TruckState 쪽에 둔다 (이름은 계산 담당이 정하고 보고에 적음. 저장에도 들어가야 껐다 켜도 같은 바퀴)
```

- 저장 형식이 바뀌면 `FORMAT_VERSION`을 올린다 (출시 전이라 변환 코드 없이 옛 파일은 이름 바꿔 남김: 지금 규칙 그대로).
- 그 밖에 화면이 부르는 함수의 이름·인자가 바뀌면 보고에 적는다. 조율자가 화면 담당에 알린다.

## 시뮬 (`tools/tune_sim.py`)

- 가상 유저가 **등급업이 뜨면 받는다** (`_reports/v4_tune_sim.diff` 내용. 바깥 폴더).
- 새 오버부스트, 소수점 적재량(평균값), 기름값 20% 반영.
- 판정: 30일째 지금 단계 중앙값. 가볍게(하루 2.5시간) +18, 열심히(하루 8시간) +20. **+20이 안 나오면 +19로 받아들인다. 한 단계 맞추려고 경제를 비틀지 않는다.**

## 제안 (json에 넣지 말고 보고서에 전후 표 + diff 파일로)

1. **강화 비용표** (`cost_base`, `cost_mult`): 위 숫자를 넣은 뒤 가볍게 +18 / 열심히 +20(또는 +19)에 맞는 값.
2. **스페어 드랍 확률:** 가볍게 유저 기준 **약 2주에 1개** (꺼둔 동안 포함, 하루 2.5시간 켜 둠). 정비 지식 최대(2배)면 약 1주에 1개. 열심히 유저는 그만큼 더 자주(몇 일에 1개인지 적음). 스페어 가격 500만은 그대로.
3. **옵션 한 줄의 가치:** +18·스포츠 기준으로 이동 속도 / 기름값 절감 / 적재량 / 오버부스트 한 줄의 시간당 수입 효과(%) 표. 목표는 "모두 이동 속도 한 줄의 절반~비슷". 안 맞는 옵션은 어떤 수치면 맞는지.
4. 퍼진 뒤 원래 단계까지 걸리는 수입 일수(가볍게): +18, +19, +20. (v6b에서 대형·VIP 단가를 정할 때 쓸 기준선. 목표 2~3주치)
