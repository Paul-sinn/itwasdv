# 경제 시뮬 방법

## 목표 (`docs/GAME_PLAN.md` 4.11, 4.2)

| 플레이어 | 하루 켜두는 시간 | 30일 후 |
|---|---|---|
| 가볍게 | 2~3시간 | +18 (퍼짐 구간 입문) |
| 열심히 | 8시간 이상 | +20 |

- 첫 튜닝(강화)은 30분 안에 해 볼 수 있어야 한다.
- 꺼둔 동안 수익은 켜 둔 것보다 항상 적다(장르 핵심: 켜 두는 게 이득).
- 사용자가 다른 목표를 주면 그것을 쓰고 보고 맨 위에 적는다.

목표 강수는 "중간값 플레이어"로 본다. 평균은 운 좋은 소수가 끌어올려서 체감과 다르다.

## 순서

1. **시뮬이 게임과 같은지 본다.** 지시서 "계산식"과 시뮬 코드를 비교한다. 다르면 숫자를 건드리지 말고 그 차이부터 보고한다.
2. **지금 값을 잰다.** seed를 고정해 돌린다(`-I`: 다른 폴더 파이썬 파일이 끼어들지 않게, `-X utf8`: 막대그래프 글자).
   ```bash
   cd "C:/Users/PAUL SHIN/OneDrive/바탕 화면/itwasdeliverd/<작업 폴더>"
   python -I -X utf8 tools/delivery_sim.py
   python -I -X utf8 tools/tune_sim.py --hours 3 --seed 7
   python -I -X utf8 tools/tune_sim.py --hours 8 --seed 7
   ```
   시뮬이 목표 플레이어(하루 시간, 30일)를 표현하지 못하면 시뮬 맨 위 "시뮬 전용 가정"에 옵션을 더한다. 게임 숫자를 시뮬 코드에 쓰지 않는다.
3. **한 묶음씩 바꾼다.** 바꾸는 곳은 `balance.json`뿐이다. 보통 이 순서로 손댄다: `engine.cost_hours`(속도 전체) →
   `engine.success`(특정 구간) → `income.star_mult*`(후반 가속) → `tune`. 퍼짐 확률(`destroy`)과 공개된 확률표는
   기획서가 [확정]한 값이 있으면 건드리지 않는다.
4. **다시 잰다.** 목표 안에 들면 멈춘다. 5번 바꿔도 안 들어가면 "숫자로는 안 됨"과 근거를 보고한다.
5. **게임이 새 숫자를 받는지 본다.** `balance.gd` 검사에 막히지 않는지 `tests/run_tests.gd`를 돌린다(`godot-build` 명령 참고).
