# 지시서 쓰는 방법

지시서는 두 에이전트가 서로 말하지 않고도 맞물리는 코드를 만들게 하는 유일한 공유 문서다. 애매한 곳은 두 쪽이 다르게 채운다.

## 쓰기 전에

1. `docs/GAME_PLAN.md` 10장(MVP)과 14장(바로 할 일), `CLAUDE.md` "현재 작업", 가장 최근 지시서, `docs/IDEAS.md`를 읽는다.
2. 이번에 만들 기능을 **하나의 질문**으로 줄인다. 예: "명장 방문 토요일이 기다려지나?" 질문이 두 개면 시제품도 두 개로 나눈다.
   한 번에 많이 넣으면 플레이 테스트에서 무엇이 재미를 냈는지 모른다.
3. **기획서와 지금 코드가 다른 곳**을 목록으로 만든다(예: 실패 시 하락 여부, 등급 이름, 리맵 방식). 이번 기능에 걸리는 것은
   지시서 "정한 것"에서 하나씩 정한다. 사용자가 정할 일이면 `grilling` 스킬로 묻는다. 사용자가 "계속 진행"처럼 맡겼으면
   추천안으로 정하고 맨 위에 "추천안으로 정함"이라고 적는다.
4. 기획서 [초안] 숫자는 `balance.json`에 넣고 `econ-sim`으로 확인할 대상이라고 적는다. 지시서에 숫자를 확정값처럼 박지 않는다.

## 형식 (`docs/PROTOTYPE_V2.md`가 본보기)

```
# 시제품 vN 지시서: <기능>
> 날짜, 확정 여부, 숫자는 balance.json 어느 묶음에

## 이 시제품으로 알아낼 것 (딱 하나)
## 정한 것            표: 항목 | 정한 것  (기획서와 다른 점은 여기서 정리)
## 계산식             돈·확률이 어디서 어떻게 정해지는지. 시뮬도 이 식을 따른다
## 코드 약속 (계산 담당 ↔ 화면 담당)
   파일별로 GDScript 시그니처 + 한 줄 뜻. 화면은 이것만 부른다.
   굴리기가 들어가는 새 시스템은 전용 파일 하나를 정한다. 저장 형식 번호와 예전 형식 읽기 규칙.
## 범위               만드는 것 / 안 만드는 것(→ IDEAS.md)
## 작업 순서와 담당    단계별: 담당(계산·window·vN-core / 화면·town·vN-ui), 고치는 파일, 안 건드리는 파일, 완료 기준
## 플레이 테스트       사용자가 직접. 5문항, "아니오" 2개 이상이면 숫자·연출부터
```

## 지켜야 할 것

- **완료 기준은 명령으로 확인할 수 있게** 쓴다. "잘 된다" 대신 "`check_x.gd`에서 7부위 각각 일반 → 전설, 10만 번 굴려 1%p 안쪽".
  QA가 근거로 쓸 수 있어야 한다.
- **고치는 파일을 담당별로 겹치지 않게** 나눈다. 겹치면 합칠 때 충돌한다. `docs/IDEAS.md`는 누구도 고치지 않는다(조정자가 모음).
- **화면에 보이는 이름**은 기획서 5장 용어 표를 따른다. 아직 바꾸지 않을 용어가 있으면 "정한 것"에 이유와 함께 적는다.
- **MVP(10장) 밖 기능**은 "안 만드는 것"으로 보낸다. 기획서 13장의 1순위 위험이 범위 폭주다.
- 진짜 창 확인이 필요한 항목은 "사용자에게 먼저 묻고 한 번에 몰아서"라고 적는다.

## 쓰고 나서

1. 사용자에게 "알아낼 것", "정한 것", "범위"를 짧게 보여 주고 확인받는다.
2. `CLAUDE.md` "폴더"에 새 지시서 한 줄을 넣는다.
3. 코드 약속의 껍데기 함수(기본값만 돌려줌)를 `scripts/core/`에 넣어 커밋한다. 화면 담당이 계산 담당을 기다리지 않고 시작할 수 있다.
