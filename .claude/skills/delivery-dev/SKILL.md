# 택배 게임 개발 오케스트레이터

메인 세션이 **조정자**다. 지시서를 쓰고, 에이전트를 부르고, 가지를 합치고, 사용자에게 보고한다.
`Workflow` 도구는 쓰지 않는다. 단계가 적고 사용자 확인이 사이사이 끼기 때문이다.

## 에이전트 구성

| 이름 (`name`) | `subagent_type` | 스킬 | 작업 폴더 / 가지 | 실행 모드 |
|---|---|---|---|---|
| `core` | `core-dev` | godot-build | `itwasdv-window` / `vN-core` | 지속형 (이름 붙여 실행, SendMessage로 이어 가기) |
| `ui` | `ui-dev` | godot-build | `itwasdv-town` / `vN-ui` | 지속형 |
| - | `qa-checker` | qa-check | `itwasdv` / `prototype-vN` | 서브에이전트 (한 번 받고 끝) |
| - | `balance-tuner` | econ-sim | 숫자를 고칠 가지의 폴더 | 서브에이전트 |

폴더는 모두 `C:\Users\PAUL SHIN\OneDrive\바탕 화면\itwasdeliverd\` 아래. 세 폴더는 같은 git 저장소의 작업 폴더라서
`git worktree list`로 지금 어느 가지인지 확인할 수 있다.
`core`·`ui`를 지속형으로 두는 이유: QA 실패를 고치거나 "vN-core 합쳐라"를 받을 때 앞서 만든 내용을 기억해야 다시 설명하지 않는다.

## 0단계: 어디까지 왔나

1. `CLAUDE.md` "현재 작업", 가장 큰 번호의 `docs/PROTOTYPE_Vn.md`, `git worktree list`, 각 가지 `git log --oneline -5`를 본다.
2. 갈래를 고른다.
   - **새 버전**: 최근 지시서가 끝났고(플레이 테스트까지) 사용자가 새 기능을 원함 → 1단계
   - **진행 중 이어서**: 지시서는 있고 단계가 남음 → 남은 단계부터. 이미 띄운 `core`/`ui`가 있으면 SendMessage로 이어 가고, 없으면 새로 띄우며 "이전 커밋부터 이어서"라고 알린다
   - **일부만 다시**: "계산만", "QA만", "밸런스만" → 그 담당만 부른다
3. 작업 폴더에 커밋 안 된 변경이 있으면 멈추고 사용자에게 묻는다. 남의 작업일 수 있다.

## 1단계: 지시서 (조정자가 직접)

1. `spec-writing` 스킬로 `docs/PROTOTYPE_Vn.md`를 쓴다. 기획서와 코드가 다른 곳, 사용자가 정할 일은 이때 묻는다.
2. 사용자 확인을 받은 뒤 가지를 만든다.
   ```bash
   B="C:/Users/PAUL SHIN/OneDrive/바탕 화면/itwasdeliverd"
   git -C "$B/itwasdv" checkout -b prototype-vN
   # 지시서 + 껍데기 함수 커밋 (spec-writing "쓰고 나서")
   git -C "$B/itwasdv-window" checkout -b vN-core prototype-vN
   git -C "$B/itwasdv-town"   checkout -b vN-ui   prototype-vN
   ```

## 2단계: 구현 — 실행 모드: 지속형 에이전트

1. 한 메시지에서 둘을 같이 띄운다(백그라운드).
   - `Agent(name: "core", subagent_type: "core-dev", prompt: ...)`
   - `Agent(name: "ui", subagent_type: "ui-dev", prompt: ...)`
   - 프롬프트에 넣을 것: 지시서 경로, 맡을 단계, 작업 폴더 전체 경로, 가지 이름, "godot-build 스킬을 따르고 완료 보고 형식으로 답하라",
     "각 단계가 끝나면 멈추고 보고하라"
2. 보고가 오면:
   - **core 단계 완료** → `SendMessage(to: "ui", "vN-core에 k단계 커밋 <해시>. git merge vN-core 하고 확인 다시")`
   - **약속 변경 요청** → 조정자가 정한다. 받아들이면 지시서 "코드 약속"을 고쳐 커밋하고, 두 에이전트 모두에 바뀐 줄을 보낸다.
     한쪽만 알면 합칠 때 어긋난다
   - **질문** → 지시서로 답할 수 있으면 답하고, 아니면 사용자에게 묻는다
   - **아이디어** → 조정자가 `docs/IDEAS.md`에 한 줄씩 모은다

## 3단계: 합치기와 확인 — 실행 모드: 서브에이전트

1. 두 담당이 모두 완료 보고하면 `itwasdv`(`prototype-vN`)에서 `git merge vN-core`, `git merge vN-ui`.
   `scripts/core/` 충돌은 vN-core 것을, `scripts/ui/`·`scenes/` 충돌은 vN-ui 것을 받는다. 그 밖의 충돌은 직접 읽고 푼다.
2. 한 메시지에서 병렬로 부른다.
   - `qa-checker`: 확인할 폴더 `itwasdv`, 지시서 경로, 이전 버전 가지 `prototype-v(N-1)`
   - `balance-tuner`: 이번에 `balance.json`이나 돈 계산식이 바뀌었을 때만. 숫자 제안만 받고 커밋은 하지 않게 한다
3. QA 실패 → 책임 쪽(`core`/`ui`)에 실패 줄과 다시 돌릴 명령을 SendMessage로 보낸다 → 고친 커밋을 다시 합친다 → QA 다시.
   **3바퀴**를 돌아도 남으면 멈추고 사용자에게 남은 실패와 함께 보고한다. 같은 실패가 계속되면 지시서가 애매한 경우가 많다.
4. 밸런스 제안 → 사용자에게 전후 표를 보여 주고, 받아들이면 조정자가 `balance.json`을 고쳐 커밋하고 `run_tests`를 다시 돌린다.

## 4단계: 사용자 확인

- 진짜 창이 뜨는 확인(`*.ps1`, `shot_screens.gd`)은 **사용자에게 먼저 묻고** 한 번에 몰아서 돌린다. QA·담당 보고의 "눈으로 볼 것"을 모아 보여 준다.
- 지시서 맨 아래 플레이 테스트 문항과 게임 실행 명령(PowerShell, `&` 포함)을 준다.

## 5단계: 정리

1. `CLAUDE.md` "현재 작업"을 고친다: 끝난 것, 남은 것(사용자가 직접 할 것 포함).
2. `docs/IDEAS.md`에 모은 아이디어, 플레이 테스트 결과를 적는다.
3. 커밋한다. push는 사용자가 말할 때만.
4. 보고: 뭘 만들었나 / 어떻게 실행하나 / 뭘 확인하면 되나 (CLAUDE.md 규칙 5).

## 데이터 전달

| 무엇 | 어떻게 |
|---|---|
| 할 일, 약속, 완료 기준 | `docs/PROTOTYPE_Vn.md` (두 담당이 같이 읽는 유일한 문서) |
| 만든 코드 | 가지 `vN-core` / `vN-ui` 커밋 → `prototype-vN`에 합침 |
| 완료·질문·약속 변경 | 에이전트 → 조정자 보고 메시지, 조정자 → 에이전트 SendMessage |
| QA·밸런스 결과 | 서브에이전트 반환 메시지 (조정자가 요약해 사용자에게) |

`_workspace/` 폴더는 만들지 않는다. 이 프로젝트는 단계마다 커밋하고 지시서·`CLAUDE.md`에 남겨서 나중에 다시 볼 수 있다.

## 오류 처리

| 상황 | 대응 |
|---|---|
| 에이전트가 답이 없음 | SendMessage로 상태를 묻는다. 그래도 없으면 같은 `subagent_type`을 새 이름으로 띄우고 "가지 X의 커밋 Y부터 이어서"라고 준다 |
| 에이전트가 실패 보고 (두 번 고쳐도 안 됨) | 출력과 짐작한 원인을 읽고, 지시서 문제면 지시서를 고쳐 다시 보낸다. 코드 문제면 한 번 더 맡기고, 그래도 안 되면 사용자에게 보고 |
| 사용량 한도·권한 거부 | 다시 시도하지 않는다. 각 가지의 마지막 커밋을 직접 보고 어디까지 됐는지 `CLAUDE.md` "현재 작업"에 적은 뒤 사용자에게 보고(한도면 풀리는 시각도) |
| 에이전트가 맡지 않은 폴더를 고침 | 그 변경을 되돌리지 말고 멈춰서 사용자에게 보여 준다 |
| 멈춘 에이전트 대신 메꾸기 | 직접 확인한 사실(커밋, 테스트 결과)만 적는다. 에이전트가 왜 그렇게 했는지는 추측해 쓰지 않는다 |

## 테스트 시나리오

**정상 흐름**: "명장 방문 만들어줘" → 0단계: v2 끝, 새 버전 → 1단계: `PROTOTYPE_V3.md`(알아낼 것: "토요일이 기다려지나?"),
사용자 확인, `prototype-v3`/`v3-core`/`v3-ui` 생성 → 2단계: `core`·`ui` 병렬, core 1단계 완료 → ui에 합치라고 알림 →
3단계: 합치기, `qa-checker` 전부 통과, `balance-tuner`가 보험 비용 숫자 제안 → 사용자 승인 → 4·5단계 보고.

**오류 흐름**: QA가 "약속: `Visit.insurance_cost(b, star)`인데 화면이 `(b)`로 부름 → 책임 화면" 보고 → `ui`에 SendMessage →
고친 커밋 합침 → QA 다시 통과. 3바퀴째에도 실패하면 멈추고 사용자에게 지시서 해당 줄과 함께 보고.
